**研究问题：执行验证的失败／成功／被证伪分支，能否帮助系统自动改进记忆编译策略，并进一步改进“产生这些策略的方法”，以更少的上下文支持新任务？**

## 核心 idea

ForkMem 已实现：任务失败 → 同代码检查点分叉 → 执行完整后续 → 保存配对证据 → 检索迁移。ForkRSI 在此基础上演化两个对象：

- **记忆编译器 C**：将 DecisionFork 转成短、带条件与证据引用的任务记忆；初版优先优化诊断提炼、适用条件和是否注入，固定检索候选池。
- **改进策略 I**：根据任务执行及候选修改的反馈，指导模型诊断并修改 C；I 本身也允许修改，新版本必须实际用于后续候选生成。

闭环：冻结任务模型执行 → 完整 verifier 与成本反馈 → I 提出 C 的修改 → 配对评估并保留版本 → 汇总改进失败，修改 I → 用新 I 继续改进 C。

例如，从中断恢复失败中提炼“各阶段分别检查完成状态，避免 applied 已完成时跳过尚未完成的 outbox／持久化阶段”，同时保留适用条件、必须保持的义务与源证据 ID。规则是待检验的经验抽象；源程序通过不代表新情境适用。

## 预期实现方式

- 复用 ForkMem 的执行器、Git 检查点、完整恢复验证、SQLite 证据存储、用例对齐和成本记录。优先检查 `counterfactual.py`、`workflows/memory.py`、`workflows/analysis.py`，通过 `agent.py` 的 `prepared_memory` 接口接入编译器。
- 为 C、I 和每次候选比较保存版本、父版本、输入证据、实际修改、任务结果及成本。策略比较单独记录，不混用任务代码分叉的 DecisionFork 语义。
- 比较候选时固定源语料、任务、初始代码、种子、模型、工具与动作预算；验证完整工作流及全部恢复用例，保留失败和退步。固定种子不视为消除了推理随机性。
- 小模型负责主要任务执行；你（也就是用户的 GPT 订阅）可辅助低频诊断和提案。各对照使用相同辅助条件，保存提示与输出。研究结论针对整个系统。
- 可自主选择模块边界、搜索与筛选方法、实验规模和任务家族。鼓励主动联网查论文全文、官方代码与模型文档，根据证据调整设计并记录理由。

重点调研： [MemEvolve](https://arxiv.org/abs/2512.18746)、[EvolveMem](https://arxiv.org/abs/2605.13941)、[GEPA](https://arxiv.org/abs/2507.19457)、[MetaSkill-Evolve](https://arxiv.org/abs/2607.05297)、[Hyperagents](https://arxiv.org/abs/2603.19461)，以及更新、更直接相关的工作。“记忆架构自演化”已有先例；须检验反事实执行证据的增量价值。

## 必要约束与评测

- 首轮租卡总预算不超过 **200 元，包含已消耗费用**；按实际余额、单价和运行时间控制规模。无新增付费 API；不训练权重、不扩大到多卡。优先复用已有下载与环境，先确认模型、JSON 协议和沙箱可运行。
- verifier、证据真实性检查和最终评测规则保持固定，不能成为自改进对象。仅完整验证通过的源分支可作为正向执行证据；局部修复不能冒充整体成功。
- 原 ForkMem 已观察过的测试结果仅作开发材料；最终评测采用新的语义约束组合。冻结后不根据测试结果修改策略或挑选展示口径。
- 最小对照包括：flat verified、原版 ForkMem、仅成功源经验驱动的编译器演化、配对及被证伪分支驱动的编译器演化。演化方法对齐搜索预算与记忆 token 上限，机制比较固定成功源程序 IDs；报告原版表示的真实成本。
- 必须进行小规模 **I 的重置比较**：让初始 I 与演化后的 I 从相同初始 C 出发，在新任务组、相同修改预算下产生候选，再评估其后代。仅最终 C 更好，不能证明“改进方法变好了”。
- 主要指标：完整安全成功率、首次验证成功率、负迁移、每任务总 tokens；同时记录源收集和搜索成本。按语义任务统计，嵌套恢复用例不能充当独立样本。

当前仓库仅包含汇总、索引和可移植案例，完整原始 runs 未提交。先检查能否获得原语料；否则收集小规模新语料。历史 47/48 对 45/48 是探索性结果，不能作为已证明的普遍优势。

## 最终交付与验收目标

交付可运行代码、配置与复现入口，C／I 版本及完整实验记录，对照结果和简短研究报告。报告回答：

1. 反事实证据是否改善了编译器修改的质量及新任务迁移？
2. 能否在降低记忆与总推理成本的同时保持或改善任务效果？
3. 演化后的 I 是否比初始 I 更会产生有效修改？

目标是完成一次或多轮（最好）真实、可复现的递归闭环和公平验证。支持正、负或不确定结果；如预算限制证据强度，应明确说明，不能将普通记忆优化包装成已证实的 RSI。
